# 接续与可选协作

用于较长任务、换对话、反馈调整或用户选择的多窗口协作。单个对话可以完成规划、实施与验收；角色可以在同一对话按任务推进。

## 按需要记录与更新

使用现有任务记录、状态文档或项目任务系统，保留一处权威入口。需要跨阶段恢复时记录：

- 当前目标、验收与已确认决定。
- 实际目录、分支及当前改动归属。
- 运行任务、恢复方式和实际产物位置。
- 已完成的验证、下一步以及影响推进的具体条件。

有新的持久信息、可恢复的阶段成果、决定变化、需要外部条件、交接或结束时，当前执行者主动更新。小任务合并到已有记录，检查过程无需逐次落盘；后台自动更新或消息推送需要实际工具与安排，文档自身不触发它们。

## 新想法与实施反馈

追问、猜想和探索性建议先在对话中澄清，保持当前主线；形成值得保留的候选项时再合入现有记录。确定采用后更新相关计划和验收；属于当前任务的纠正与补充直接并入，用户要求切换目标时保存现有阶段状态后调整。

范围内的实现问题由执行者定位、修复和验证。改变目标、核心路线、预算或验收的反馈说明现象与证据、影响、已有尝试、建议和交付关系；只调整受影响部分，保留仍有效的目标、实现与对照。

对能够补足的不确定性先执行补足；将需要用户决定的事项集中为具体选项。真实阻断时交付已完成部分和恢复办法，其他独立工作继续推进。

## 明确选择协作时

| 角色 | 主要职责 |
|---|---|
| 规划或任务负责人 | 目标、技术取舍、优先级、任务卡及结果判断 |
| 执行者 | 实施、必要验证、实际效果、产物整理与交接 |
| 独立复核者 | 针对明确问题核对证据和结果，将发现反馈给负责人 |

角色和数量由任务、工具、成本及用户/项目选择决定；普通任务由一位执行者负责即可。

共享同一目录时，通过任务与状态文件衔接，协调同一文件的写入者。不同 worktree 或目录有各自文件状态，需要明确版本及合入方式，本地资源另行核对。

聊天内容不会因为同属一个项目就自动互通。现有工具支持且用户/项目已授权时可协调指定对话或子 agent，主执行者负责汇总、验证和落盘；长期接续仍以实际文件和状态为依据。

## 选择简短指令

以下模板中的占位内容换成实际目标；项目文件名用本项目现有入口。按当次操作选一段即可，长期规则由技能与项目说明承载。

**接手或持续执行**

```text
使用 $make-it-lean，读取项目现有约定与当前任务，围绕“〔目标〕”自主完成实施、必要验证、产物清理、状态更新和已授权的 Git 交付。需要补足的问题在过程中处理，交付实际结果与入口。
```

**先完成规划**

```text
围绕“〔目标〕”完成必要调查与技术取舍，把方案、输入、交付及验收写入现有计划，给出可直接实施的短指令。本轮交付为规划。
```

**调整反馈或并入新想法**

```text
结合“〔反馈或想法〕”及实际证据，判断与现任务的关系，在原目标内处理可以自行决定的调整，将需要的方案与验收变化写回现有记录，给出下一项具体动作。
```

**交接或换对话**

```text
在合适节点整理当前目标、实际目录与分支、已完成改动、运行任务、验证结果、恢复方式和下一动作，更新现有状态入口，完成可交付步骤的整理与已授权同步，给出一句接续指令。
```

执行中反复遗漏已确认决定时，先重读现有状态；需要换对话时使用最后一段保存接续。主要模型切换也在明确的任务节点交接，当前型号和预算由用户及项目选择。
